# VAULT TRUST LAB

## 현재 구현 범위

`app/`은 TESSERA와 DIGITAL VAULT가 하나의 클라이언트 암호화 경계를 공유한다는 제품 가설을 검증하는 Trust Lab MVP다.

- Supabase Auth 기반 초대 전용 VAULT ID 로그인
- 최초 로그인 비밀번호 변경과 TOTP 인증 앱 등록
- AAL2 세션을 요구하는 데이터베이스 RLS
- AAL2 조직 관리자 전용 임시 VAULT 계정 발급
- 조직 관리자 전용 구성원 목록과 복구 가능한 로그인 정지·복구
- 관리자 자신과 다른 관리자 계정의 접근 변경 차단
- 앱을 다시 열 때 서버에서 접근 정지 상태 재확인
- 실명·실제 이메일·휴대폰 번호 미수집
- 브라우저 메모리에서 비추출 AES-GCM 키 생성
- 메시지 암호화·복호화 round-trip 검증
- 파일별 키를 이용한 실제 파일 암호화·복호화
- 파일 키 폐기 후 접근 불가 상태 시연
- 메시지 본문과 파일명을 포함하지 않는 로컬 감사 이벤트
- 메시지·파일 평문이 서버로 전송되지 않는 세션 전용 데모 구조

이 구현은 투자자와 디자인 파트너에게 제품 원리와 Golden Path를 보여주는 기술 시연이다. 계정과 공개 기기 정보는 Supabase에 유지되지만 메시지·파일 콘텐츠는 로컬 데모 범위에 머문다. 완성된 E2EE 메신저, 디지털 금고, 상용 보안 제품 또는 규제 준수 제품이 아니다.

## 실행

저장소 루트에서 정적 서버를 실행한 뒤 `/app/`에 접속한다.

```text
http://localhost:{port}/app/
```

`file://`에서도 일부 화면은 열리지만 Web Crypto와 파일 동작 검증은 로컬 HTTP 환경에서 수행한다.

## 다음 구현 단계

### 1. Identity Spike

- 구성원 접근 정지·복구 Golden Path 검증
- 계정 발급·권한 변경·폐기 감사 이벤트의 서버 기록
- 사용자·기기 식별자 분리
- 기기별 키 생성과 안전한 로컬 보관
- 신규 기기 검증과 기기 폐기
- 사용자 복구 키 UX 검증

### 2. Messaging Spike

- Matrix homeserver와 `matrix-js-sdk` 기술 검증
- 1:1 암호화 대화
- 3~10명 소규모 그룹
- 기기 간 세션 및 키 복구
- 암호화 첨부파일
- 라이선스와 배포 구조 검토

### 3. Archive Spike

- 대용량 스트리밍 파일 암호화
- 파일별 키와 수신자별 키 래핑
- 암호화된 Object Storage 업로드
- 파일 접근 취소와 만료
- 파일명·메모 등 민감 메타데이터 암호화 범위 결정

### 4. Control Plane

- Supabase Auth·Postgres·Storage 기술 검증
- 조직·멤버십·역할 모델
- 모든 공개 테이블의 RLS
- 콘텐츠를 포함하지 않는 감사 이벤트
- 서비스 역할 키의 서버 전용 관리

### 5. Security Gate

- 위협 모델 확정
- 서버·로그·백업 평문 미저장 자동 검사
- 키 분실·기기 분실·멤버 퇴장 시나리오
- 외부 암호 구현 검토 범위 확정
- 외부 검토 전 보안 인증 및 절대 보안 표현 금지
